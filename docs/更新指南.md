# 更新指南

本文说明统一启动器里四条互不重叠的更新通道、各自的校验与回滚方式，以及升级
ZHS 核心、维护依赖清单、发布新版本时的具体步骤。

| 对象 | 更新方式 | 校验 | 失败处理 |
| --- | --- | --- | --- |
| 统一启动器（外壳 + `src/`、`web/`） | 启动器自更新 | Release 清单中的 SHA-256 | 保留旧文件，提示重试 |
| Yatori 核心 | 界面「检查版本 → 安装更新」 | 发布方 SHA-256 + 大小 | 暂存目录切换，自动恢复旧核心 |
| Autovisor 核心 | 只检查版本，禁止覆盖安装 | — | 需人工合并上游改动 |
| ZHS 核心（`zhs/`） | 中控台「检查更新」或 `scripts/update_zhs.py` | 本地哈希清单 + 安装前备份 | 自动回滚 `zhs/` |

## 1. 统一启动器自更新

自 v1.7.1 起，自动更新替换 `统一启动器.py`、`requirements.txt`、`bootstrap.py`、
`requirements-zhs.txt`、`src/`、`web/`、`zhs/`（`scripts/build_launcher_release.py`
的 WHITELIST、`src/launcher_update_service.py` 的 REPLACE_WHITELIST 与
`launcher-manifest.json` 的 `replaceWhitelist` 三处保持一致）。

自动应用流程：

1. 下载 → 校验大小与 SHA-256 → 解压到 `.update-staging/`。
2. 启动器拉起 `.update-staging/应用更新.cmd` 并自行退出。
3. 脚本等待旧进程退出，把现有文件备份到 `.update-backup/`，替换白名单条目，
   逐文件 `fc /b` 比对；任一步失败自动回滚。
4. 执行 `bootstrap.py --prepare-zhs --quiet` 准备 `.runtime/venv-zhs`（ZHS 依赖）。
5. 自动重启启动器；成功路径不 `pause`，失败或手动模式才停住提示。

核心任务（Yatori / Autovisor / 练习 / ZHS）运行中时，自动应用会推迟到退出
启动器时执行，不打断正在跑的任务。

`launcher-manifest.json` 同时给出两份文件清单：

- `fileList`：只含 `统一启动器.py`、`requirements.txt`、`src/`、`web/`，这是
  v1.7.0 及更早客户端会替换的范围。旧客户端把整份 `fileList` 当作「必须替换
  成功」的清单，混入 `bootstrap.py`、`zhs/` 等它不会复制的路径就会回滚。
- `fullFileList`：完整清单，v1.7.2 起的更新器用它做完整性校验。

更新完成后的首次启动还会自检 ZHS 环境：缺失且用户已配置过 ZHS 时，后台运行
`src/zhs_runtime_prepare.py` 补建 `.runtime/venv-zhs`，旧版 bootstrap.py
（没有 `--prepare-zhs`）也能生效。

因此下面这些内容**仍然不会**被启动器自更新覆盖，需要完整包或手工同步：

- `Autovisor/`、`Yatori/`、`scripts/`、`docs/`、`data/`

老用户继续用 `launcher-<version>.zip`；改变目录结构、依赖或 bootstrap 行为时，
需要发布新的完整包 `shuake-toolkit-<version>.zip`。

## 2. Yatori 核心更新

- 版本来源：GitHub Release API。
- 只接受 API 提供有效 `sha256` 的资源；下载后再核对大小与 SHA-256，校验
  通过后才解压。
- 在独立临时目录完成下载、解压、入口识别和新版本暂存，再同盘切换；切换失败
  自动恢复旧核心。
- 用户配置只从当前使用的 `Yatori/config.yaml` 继承。

## 3. Autovisor 核心

当前 `Autovisor/` 是项目本地适配版（扫码登录、依赖自检、退出码兜底等），
Web 界面**只检查上游版本**，不提供覆盖安装。同步上游时人工合并到
`Autovisor/`，然后跑全量回归：

```powershell
& D:\Python\python.exe -m pytest tests -q --basetemp=.pytest-tmp
```

## 4. ZHS 核心更新（重点）

### 4.1 在界面里更新

1. 打开启动器 → **中控台** → 「智慧树 ZHS」卡片 → **检查更新**。
2. 弹窗显示本地版本、上游最新版本、归档名、更新时间、上游说明与外链。
   - 已是最新时「安装更新」按钮禁用；
   - 本地版本高于上游时不会降级。
3. 点「安装更新」后进度条依次显示：正在下载 → 正在安装（同步源码 + 重装环境）
   → 更新完成。
4. **更新完成后重启启动器**，新版本才生效（当前进程已导入旧代码）。
5. 更新前必须先停止 ZHS 与题库外的相关进程；ZHS 正在运行时安装会被拒绝。

### 4.2 更新过程中做了什么

`src/core_manager.py::install_zhs` + `src/zhs_vendor.py` 的固定顺序：

1. 下载上游 tag 源码归档（GitHub 直连与镜像并发测速，失败自动换源）。
2. 计算并记录归档 SHA-256；以 `tag:<版本>` 作为来源标识。
3. 把现有 `zhs/` 备份到 `zhs-backup-<时间戳>`。
4. `vendor.sync_from_source`：
   - 先用 `UPSTREAM.sha256` 检查本地是否被改动（有漂移且未 `force` 则中止）；
   - 比较与覆盖时统一做 **CRLF → LF 归一化**，避免 Windows 检出换行导致
     「全部文件已修改」；
   - 只覆盖 `SYNC_ENTRIES`：`src/`、`pyproject.toml`、`LICENSE`、`CHANGELOG.md`、
     `README.md`、`README_zh.md`、`config.toml.example`、`uv.lock`；
   - 删除上游已移除的文件（不碰元信息文件）；
   - 重写 `UPSTREAM.sha256` 与 `UPSTREAM.json`（记录版本、上游提交、时间、
     `local_patches: []`）；
   - 按新版 `pyproject.toml` 的 `[project].dependencies` 重写仓库根
     `requirements-zhs.txt`。
5. 在 `.runtime/venv-zhs` 里 `pip install -e zhs --no-deps` 重装 editable 包。
6. 按 `requirements-zhs.txt` 安装依赖（清华/阿里/华为/官方四个镜像依次重试，
   每个 15 分钟超时）。
7. 冒烟检查：`zhs --version`、`play --help`、`fetch --help`、`homework --help`、`exam --help`。
8. 记录 `.core_versions.json` 的 `zhs` 版本为 tag，删除备份目录。

任何一步抛异常：删除新 `zhs/`，把 `zhs-backup-<时间戳>` 换回原位，日志以
「已回滚到旧版 zhs」结束，界面显示失败原因。

### 4.3 数据与登录态

更新只替换 `zhs/` 源码，下列内容保持不变：

- `data/zhs/account-1/.zhs/config.toml`（运行参数、AI、题库配置）
- `data/zhs/account-1/.zhs/cookies.json`（扫码登录态）
- `data/zhs/account-1/.zhs/execution.json`（拉取到的课程列表）
- `data/zhs/account-1/.zhs/logs/`
- `.runtime/venv-zhs` 解释器本身（只增量安装依赖）

若上游改了配置字段名，旧 `config.toml` 仍可加载，缺失键走新版默认值。

### 4.4 命令行维护者流程

```powershell
# 1) 只校验内置副本有没有被改过（零补丁检查）
py scripts\update_zhs.py --check

# 2) 与新版目录比较，不写盘
py scripts\update_zhs.py --source D:\Python\zhs2123\zhs --dry-run

# 3) 正式同步（有本地改动会中止，确认丢弃时加 --force）
py scripts\update_zhs.py --source D:\Python\zhs2123\zhs --force
```

脚本会依次执行同步、重装、依赖同步、冒烟检查。

| 退出码 | 含义 |
| --- | --- |
| 0 | 成功 |
| 1 | 参数或目录错误 |
| 2 | 本地副本有改动（需要 `--force`） |
| 3 | editable 重装失败 |
| 4 | 冒烟检查失败 |
| 5 | 依赖安装失败 |

其他参数：`--repo-root`（默认仓库根）、`--skip-smoke`（只同步）、`--git-rev`、`--source-url`。

### 4.5 安全说明

ZHS 上游只发布 tag 与源码归档，**没有发布方 SHA-256 摘要**。因此这条通道不等同
于 Yatori 的强校验，而是「官方 tag 归档 + 本地哈希记录 + 安装前备份 + 失败回滚」。
归档 URL 固定来自 `https://github.com/pjm314159/zhs/archive/refs/tags/<tag>.zip`，
弹窗与日志都会明确提示这一点。

## 5. 依赖清单

| 文件 | 用途 |
| --- | --- |
| `requirements.txt` | 启动器 + Autovisor 基础依赖（与 `src/dependencies.py` 的 CORE_DEPENDENCIES 对齐，有测试断言） |
| `requirements-zhs.txt` | ZHS 独立环境（`.runtime/venv-zhs`），**由 pyproject 自动生成，不要手改** |
| `requirements-optional.txt` | 不用 `Autovisor/runtime_deps` 时的 numpy/opencv |
| `requirements-dev.txt` | 测试与开发（pytest、httpx） |
| `Autovisor/requirements-web.txt` | 实验性 FastAPI Dashboard |

校验环境：

```powershell
py bootstrap.py --check
```

会逐项检查 Python 版本、`requirements.txt`、Playwright、WebView2、
`Autovisor/runtime_deps` 的 cv2/numpy，以及 `zhs/pyproject.toml`、`requirements-zhs.txt`、`.runtime/venv-zhs`。
缺依赖时执行：

```powershell
py bootstrap.py --install --no-launch
```

其他 ZHS 相关参数：`--prepare-zhs`（只准备 ZHS 环境，不安装其他依赖、不启动启动器，启动器自更新会调用它）、`--skip-zhs`（跳过 ZHS 环境）、`--zhs-venv-dir`。
ZHS 环境要求 **Python 3.13/3.14**（`zhs` requires-python `>=3.13,<3.15`）；启动器本体仍支持 3.11–3.13。找不到合适解释器时 bootstrap 只告警并跳过，
界面会显示「ZHS 环境尚未就绪」，可单独安装 3.13 后重跑。

## 6. 常见问题

| 现象 | 处理 |
| --- | --- |
| 检查更新报 403 / 超时 | GitHub API 有匿名限流，启动器会自动走镜像与 releases 页面兜底；仍失败时检查网络或稍后重试 |
| 更新成功但版本没变 | 重启启动器；版本记录在 `.core_versions.json` 的 `zhs` 字段 |
| 更新时提示「本地有改动」 | 说明 `zhs/` 被手工改过；确认不需要保留后加 `--force`，或先 `--check` 查看清单 |
| 依赖安装很慢 / 卡住 | 镜像对大 wheel 可能很慢；可在维护者机器上设 `$env:PIP_INDEX_URL='https://pypi.org/simple'` 后手动 `pip install -r requirements-zhs.txt` |
| 更新失败后如何确认回滚 | 看日志「已回滚到旧版 zhs」；仓库根不应残留 `zhs-backup-*`，`zhs/UPSTREAM.json` 版本应为旧版 |
| 界面提示 ZHS 环境未就绪 | `py bootstrap.py --check` 看缺哪项；需要 3.13/3.14 与 `.runtime/venv-zhs` |
| ZHS 启动后弹 cmd 窗口 / 日志刷屏 | 已在 0.1.5 集成层修复；确认启动器是最新完整包（这两处改在 `src/`，随启动器更新） |
| Playwright 报 `EPERM ... mkdtemp`，或导出日志时 explorer 弹 0xc0000142 | 工作区文件带 Low 完整性标签，子进程无法写 `%TEMP%`。在仓库根执行 `icacls "." /setintegritylevel Medium /t /c /q` 与 `icacls "." "/setintegritylevel" "(OI)(CI)Medium"`（注意第二句的括号要加引号），然后重启启动器 |

## 7. 发布新版本

1. 更新代码并跑全量测试：
   `& D:\Python\python.exe -m pytest tests -q --basetemp=.pytest-tmp`。
2. 需要随包发 `zhs/` 时，先 `py scripts\update_zhs.py --check` 确认零补丁。
3. 构建启动器增量包：`py scripts\build_launcher_release.py`。
4. 改过 `bootstrap.py`、`requirements-zhs.txt`、`zhs/` 或目录结构时，必须同时
   发布完整包 `shuake-toolkit-<version>.zip`（`full-manifest.json` 由构建脚本生成）。
