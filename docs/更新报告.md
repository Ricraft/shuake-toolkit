## 二、新增核心：智慧树 ZHS

### 2.1 定位与运行方式

- 作为第三个核心与 Yatori、Autovisor 并列，不替换任何现有核心；课程提供方仍复用启动器已有的 `zhs` 账号体系与课程缓存。
- 内置上游 [pjm314159/zhs](https://github.com/pjm314159/zhs) 的零补丁副本：版本 `0.1.5`（上游 git `50bd236`），79 个文件，GPL-3.0-only，许可证与来源记录在 `zhs/LICENSE`、`zhs/NOTICE.md`、`zhs/UPSTREAM.json`、`zhs/UPSTREAM.sha256`。
- 独立解释器环境 `.runtime/venv-zhs`（Python 3.13/3.14），只装 ZHS 依赖，避免与启动器 Playwright 环境互相污染。
- 启动方式：`.runtime\venv-zhs\Scripts\python.exe -m zhs play ...`，工作目录 `data/zhs/account-1`，单账号串行。
- 不依赖 Playwright、不打开浏览器、不弹控制台窗口（`CREATE_NO_WINDOW`）；进程输出经 `src/process_supervisor.py` 进入统一控制台。

### 2.2 登录与会话

- 扫码登录：启动器内嵌 passport 协议（`src/zhs_bridge/qr_login.py`），点「获取二维码」约 2 秒出码，二维码显示在配置页，同时落盘 `data/zhs/account-1/.zhs/qrcode.png`；支持「取消登录」「刷新登录态」「清除凭证」。
- 真实会话校验：`src/zhs_bridge/session_check.py` 用 cookies 走 CAS 换票 + `getLoginUserInfo`，返回 `ok / expired / unavailable / none / error`；过期时徽标变红并提示「登录已过期，请重新扫码」，不再出现“凭证已失效却显示已登录”。
- 取消登录会删除本地 `cookies.json` 并复位为未登录，修复了取消后状态变成“扫码登录失败：返回码 1”的竞态。
- 登录态校验结果按 cookies 文件 mtime 缓存（成功 5 分钟、异常 30 秒），面板打开时后台补校验，不阻塞 UI。

### 2.3 课程与运行

- 拉取课程：`python -m zhs fetch` 写入 `.zhs/execution.json`（知到 / hike / AI 三类），不再依赖 Playwright 抓页面；课程列表展示为「课程名（课程 ID）」。
- 课程选择：支持多选、全选/取消全选，勾选结果持久化（保存配置、切页、扫码轮询后不会被重置）。
- 多门课程：同一个 zhs 进程内按勾选顺序逐门串行（`play -c A -c B`），不开并行；日志开头会写明「本次课程：共 N 门（按勾选顺序逐门串行）：…」。
- 支持三种任务：开始刷课（play）、写作业（homework）、考试（默认不自动提交）。
- 考试模式确认框改为页内模态（`#zhs-exam-modal`），不再是原生 `confirm` 弹窗。
- 验证码救援：zhs 因验证码中断时（日志 `Course stopped: captcha required (racId=…, course=…, videoId=…)`），配置页出现红色提示条，提供「打开课程页验证」「只重跑这门课」「知道了」；验证完成后重跑同一 racId 即可继续。

### 2.4 日志与自动化

- 进度行补课程名：`playing 3D打印技术与应用（262043） [####] 62.5%`，同一视频的进度帧原地刷新为一行，不再每帧刷屏。
- 识别 zhs 的 `\r` 进度格式并合并；ANSI 颜色码剥离。
- 修掉子进程额外弹出可见 cmd 窗口的问题（原因：`CREATE_NO_WINDOW` 与 `DETACHED_PROCESS` 叠加会新建控制台）。
- 关掉可见控制台后，旧版「关闭窗口导致 stdout 失效、报 `[Errno 22] Invalid argument`」的问题随之消失。
- 自动关机：沿用「软件设置 → 刷完自动关机」，ZHS 整轮退出后判定；若本轮有课程因验证码或错误未完成（zhs 仍以 0 退出），则跳过自动关机并在日志中说明。

### 2.5 自动答题配置

配置页「自动答题（AI / 题库）」折叠区，字段写入 `.zhs/config.toml`：

- AI：提供商下拉（OpenAI / SiliconFlow / DeepSeek / 智谱 / 通义 / 星火 / 豆包 / MetaAI / 自定义）、Base URL（自动预览补全后的 `/chat/completions` 地址）、模型（可「获取模型」拉到 datalist）、API Key（可显示/隐藏、可连通性测试）、最大 Token。
- 第三方题库：开关、Token、查询地址（默认 `https://tk.enncy.cn/query`）。
- 运行参数：知到倍速、AI 倍速、单课观看上限、进度阈值。

### 2.6 环境与数据

- `bootstrap.py` 新增 ZHS 通道：查找 Python 3.13/3.14 → 建 `.runtime/venv-zhs` → 按 `requirements-zhs.txt` 装 12 项依赖 → editable 安装 `zhs/` → 校验；`--check` 新增三项检查。
- 新增参数 `--skip-zhs`、`--zhs-venv-dir`；没找到 3.13/3.14 时只警告，不阻塞启动器。
- 数据落在 `data/zhs/account-1/`：`.zhs/config.toml`、`cookies.json`、`execution.json`、`logs/`；删除核心或更新源码不影响这些数据。

## 三、ZHS 核心更新与依赖同步

中控台 ZHS 卡新增「检查更新」，弹窗展示当前版本、上游 tag、来源、发布时间、上游更新日志和两个外链。上游信息取自 GitHub tags，直连 403 时自动走 gh-proxy。

安装流程（`src/core_manager.py::install_zhs`，失败整体回滚）：

1. 下载 `https://github.com/pjm314159/zhs/archive/refs/tags/<tag>.zip` 并记录 SHA-256；
2. 备份现有 `zhs/` 为 `zhs-backup-<时间戳>`；
3. `sync_from_source` 覆盖源码、清理上游已删文件、重写 `UPSTREAM.*`（比较前统一 CRLF→LF，避免 Windows 换行被误判为改动）；
4. 按新版 `pyproject.toml` 自动重写 `requirements-zhs.txt`；
5. 在 `.runtime/venv-zhs` 内 `pip install -e zhs --no-deps`；
6. 清华/阿里/华为/官方四个镜像依次安装依赖；
7. 冒烟 `--version` 与 `play/fetch/homework/exam --help`；
8. 写 `.core_versions.json` 并删除备份。

运行中不允许安装（按钮置灰并说明原因）；本地版本高于上游时提示「已跳过降级更新」。命令行同样可用：`python scripts/update_zhs.py --check/--dry-run/--source/--force`，退出码 0–5。

## 四、Autovisor 改进

- **扫码登录**：账号卡新增「登录方式」下拉（账号密码（自动滑块）/ 扫码登录）。`loginMode=qr` 时打开 `passport.zhihuishu.com` 扫码页，复用核心已有的手动登录分支（24 小时等待），登录完成写回 cookies；扫码模式要求显示浏览器窗口，跳过账密校验。
- **每账号独立 Cookie**：继续写 `cookiesFile`，只有默认值（空 / `res/cookies.json`）时才改为 `res/cookies_<账号>.json`，用户自定义路径不被覆盖，修复多账号共用 cookies 互相顶掉。
- **人机验证依赖自检**：启动前探测 `Autovisor/runtime_deps` 里的 cv2/numpy，缺失自动跑 `download_runtime_deps.py`，失败退回 pip；仍失败只警告并提示手动拖滑块或改用扫码，不再阻止启动。
- **安装失败不再杀进程**：`installer.py` 的两处 `sys.exit(-1)` 改为抛异常，`Autovisor.py` 捕获后降级为手动验证模式。
- **非交互 stdin 兜底**：`Practice_Mode.py` 与 `Autovisor_Multi.py` 的 `input()` 捕获 `OSError/ValueError`，避免退出码被污染。

## 五、问题修复汇总

| 问题 | 根因 | 处理 |
| --- | --- | --- |
| Playwright 报 `EPERM mkdtemp`、explorer 弹 0xc0000142、日志导出报错 | 工作区根目录带 Low 完整性标签，子进程无法写 `%TEMP%`（20901 个文件继承） | 对工作区与两个 venv 执行 `icacls /setintegritylevel Medium`；日志导出白名单补 `zhs` |
| 点取消登录后状态变 error、旧凭证未清 | 取消先置 `cancelled` 再杀进程，收尾事件覆盖状态 | 先置 `cancelled` 再终止；worker 收尾尊重取消；取消时删除 `cookies.json` |
| ZHS 每帧进度新增一行 | zhs 用 `\r` 原地刷新，读取端把 `\r` 当换行 | 新增进度识别规则（含 `%` + 进度条字符），按「替换上一行」处理 |
| 勾选多门课保存后只剩一门 | 渲染函数固定勾第一门，且每次重渲染覆盖 | 用 `Set` 记录选择并持久化，未改动时才默认勾第一门 |
| 开始刷课弹出新 cmd 窗口 | `CREATE_NO_WINDOW` 与 `DETACHED_PROCESS` 同时设置 | 只保留 `CREATE_NO_WINDOW` + `STARTF_USESHOWWINDOW` |
| 日志导出点击报错但文件已导出 | `LOG_TABS` 不含 `zhs`，且 explorer 在 Low IL 下崩溃 | 补 `zhs`；IL 修复后 explorer 正常 |
| AI 区缺少供应商与 URL 预览 | 只做了简单字段 | 补供应商下拉、预览、获取模型、连通性测试 |
| 点「GitHub 项目主页」提示未知链接 | 动作键 `zhs_github` 未注册 | 补别名键 |
| ZHS 更新弹窗「安装更新」点了没反应 | 打开时清空 `onclick` 又被忙碌态重置 | 重排初始化顺序并绑定 `confirmZhsUpdate` |
| 失败课程仍触发自动关机 | zhs 单门失败后 `continue` 并以 0 退出 | 记录失败标记，退出时跳过自动关机 |

## 八、兼容性与升级步骤

1. 关闭启动器（正在运行的 ZHS 需先停止）。
2. 拉取本次代码后运行 `python bootstrap.py --install`；若机器上没有 Python 3.13/3.14，ZHS 环境会跳过，其余功能不受影响。
3. 打开启动器 → 核心设置 → ZHS 新版核心 → 获取二维码 → 扫码登录 → 拉取课程。
4. 已有 `data/zhs/`、`cookies.json` 可直接沿用；如提示登录过期，重新扫码即可。
5. 若再次出现 Playwright/explorer 权限错误，重跑 `icacls` 修复（见 `docs/更新指南.md` 常见问题）。

> 注意：启动器自更新只覆盖 `统一启动器.py`、`requirements.txt`、`src`、`web`，不包含 `zhs/`、`requirements-zhs.txt`、`bootstrap.py`；ZHS 源码请走「检查更新」或完整包。pip 安装若卡住，可临时 `$env:PIP_INDEX_URL="https://pypi.org/simple"`。

## 九、已知限制与后续计划

- 目前 ZHS 为单账号串行（原计划的多账号并行因风控与复杂度暂缓）；同一 IP 多账号并行存在风控风险。
- 验证码为网易易盾 JS 组件，无法在启动器内直接渲染，只能「打开课程页人工验证 + 重跑」；暂不做自动过验证。
- 考试模式默认不自动提交，且一次只能处理同类型课程；多门 AI 考试需分开运行。
- ZHS 更新只校验官方 tag 与本地 SHA-256，无发布方签名；失败依赖备份回滚。
- 后续可做：多账号并行（独立数据目录 + 错峰 + 并发上限）、更新进度条复用 Yatori 的测速选源、ZHS 课程进度解析进中控台。
