# 统一启动器 v1.7.2

本版修复「从 v1.7.0 更新到 v1.7.1 必定回滚」的兼容性问题，并让缺少 ZHS 运行环境的安装包在更新后自动补齐环境。

> 2026-11-14 核对补正：原发布版只修复了清单兼容，ZHS 文件补齐仍有缺口。
> 以下“本地补充修复”现归入 [v1.7.3](v1.7.3.md)，尚未发布到 GitHub，不能据此认为
> 既有官方 v1.7.2 资产已包含修复。详见 [逐项核对记录](../更新日志核对.md)。

## 更新内容

### 修复：v1.7.0 客户端自更新回滚

- v1.7.0 及更早客户端的替换白名单只有 统一启动器.py、requirements.txt、src、web，但它们会把 `launcher-manifest.json` 的 `fileList` 整份当作「必须替换成功」的校验清单。v1.7.1 的 `fileList` 含 bootstrap.py、requirements-zhs.txt、zhs/，旧客户端不会替换这些路径，替换后逐字节校验必然失败并回滚——表现就是「提示更新完成，重启后还是旧版本」。
- 现在 `launcher-manifest.json` 提供两份清单：
  - `fileList`：只包含 统一启动器.py / requirements.txt / src/ / web/ 下的文件，即旧客户端能替换的范围；
  - `fullFileList`：完整更新包清单。
- v1.7.2 起的更新器优先用 `fullFileList` 校验完整性，仍然要求每个文件都真正落地；v1.7.0 客户端按 `fileList` 校验即可成功完成到 v1.7.2 的更新。

### 修复：自更新后 ZHS 仍提示「未找到运行环境」

- v1.7.0 自更新脚本只替换 4 个旧白名单条目，bootstrap.py 保持旧版、也没有 `--prepare-zhs`，因此这次升级无法在更新脚本里准备 ZHS 环境。
- 原方案只复用 bootstrap helper，不能补齐旧更新器未复制的源码和依赖清单；旧 bootstrap 还可能没有这些 helper，因此原来的环境自愈承诺不完整。
- 本地补充修复：构建时生成 `src/legacy-zhs-payload.zip` 并加入旧版可校验的 `fileList`；首次启动在服务装配前事务补齐 bootstrap.py、requirements-zhs.txt 与 zhs/，保留账号配置，随后创建独立环境。
- 延迟自检仍仅对已配置过 ZHS 的用户自动准备（存在 `data/zhs/` 或 `.runtime/venv-zhs`）；7 天内自动尝试过则不反复重试，主动点击可绕过等待重试。
- 点击「启动核心」但环境仍缺失时，也会在后台触发准备，并把提示改为「正在后台准备，完成后请重新点击启动核心」，不再只报错。
- 本地补充修复也覆盖扫码登录入口；准备失败记录具体原因。仍需本机安装 Python 3.13/3.14，依赖下载需要联网。

### 本地补充修复：清理更新 ZIP 与任务收尾

- 更新脚本只在全部文件落地校验成功后删除本次下载 ZIP；失败/回滚时保留。
- 启动时仅删除根目录 `launcher-v*.zip` 或 `.update-staging/v*.zip` 中与已安装文件全部一致的包，不删除旧版本包、核心包及备份。
- “停止全部”和退出清理加入 ZHS；退出时也处理正在启动的任务，更新前先发出取消/停止请求。
- ZHS 核心更新失败时恢复源码、依赖清单及磁盘/内存版本记录；pip 已安装依赖不自动降级，不能称为完整环境回滚。

### 本地补充功能：启动版本检查与提示

- 启动后后台检查 Yatori、ZHS 和统一启动器版本；网络失败仅记录日志，不打断启动。
- 已安装的 Yatori / ZHS 有新版时在名称右上角显示 `New`；成功更新或确认无新版后隐藏。
- 启动器发现新版时自动打开详情弹窗，每次页面会话同一版本只展示一次；确认后才下载更新。
- 其他弹窗正在显示时延后展示，已被手动检查替代的确认令牌不再自动展示。
- 本地补充启动器详情页进度条：确认后保持弹窗，显示下载量、速度、剩余时间、校验与解压阶段；失败留页重试，准备完成后提示并交给进程外脚本应用。准备完成不等于文件已替换。

## 已知限制

- 从 v1.7.0 及更早版本升级到本版时，第一次仍由旧版本逻辑执行：只替换 统一启动器.py / requirements.txt / src / web，bootstrap.py、zhs/ 由首次启动后的自愈逻辑补齐；从 v1.7.2 起后续更新会完整替换全部 7 项白名单。
- ZHS 环境需要 Python 3.13/3.14；安装后重新点击扫码登录或启动核心可重试准备。
- 更新包不包含 Yatori/Autovisor 第三方核心，行为与上一版一致。
