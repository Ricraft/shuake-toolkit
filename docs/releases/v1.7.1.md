# 统一启动器 v1.7.1

本版修复 v1.7.0 暴露的启动器自更新问题：下载并校验后会自动应用更新、补齐 ZHS 运行环境并重启启动器，不再需要手动运行「应用更新.cmd」。

> 历史公告核对补正（2026-11-14）：本页描述新增更新器的行为，首次升级仍由旧更新器执行。
> v1.7.0 → v1.7.1 还存在清单不兼容导致回滚的问题，不能只靠手动执行脚本解决；
> 后续清单修复与 ZHS 文件补齐见 [v1.7.2 补正说明](v1.7.2.md)。

## 更新内容

### 修复：启动器自更新不生效

- v1.7.0 及更早版本把更新包解压到 `.update-staging/` 后只提示「退出启动器后运行「应用更新.cmd」」，用户重启启动器并不会更新，必须手动找到并运行脚本。
- 现在更新完成后启动器会主动拉起 `应用更新.cmd` 并退出自身：脚本等待旧进程退出 → 备份到 `.update-backup/` → 替换文件 → 校验失败自动回滚 → 自动重启启动器。核心任务（Yatori / Autovisor / 练习 / ZHS）运行中时，自动应用推迟到退出启动器时执行，避免打断任务。
- 自更新白名单从 `统一启动器.py`、`requirements.txt`、`src`、`web` 扩展为同时包含 `bootstrap.py`、`requirements-zhs.txt`、`zhs/`，与完整运行包保持一致；`launcher-manifest.json` 的 `replaceWhitelist` 同步更新。

### 修复：更新后 ZHS 提示「未找到运行环境」

- 自更新流程在替换完成后立即执行 `bootstrap.py --prepare-zhs --quiet`，创建/更新 `.runtime/venv-zhs` 并按 `requirements-zhs.txt` 安装依赖，再启动新启动器；ZHS 运行环境不再要等到首次点「启动核心」才暴露缺失。
- `bootstrap.py` 新增 `--prepare-zhs` 模式：只准备 ZHS 环境，不安装其他依赖、不启动启动器。环境准备失败只告警，不影响启动器本身升级，可在 ZHS 页面重新准备。

### 改进：更新流程与核心更新对齐

- 启动器更新采用「暂存 → 备份 → 替换 → 校验 → 失败回滚」流程，替换后逐文件 `fc /b` 对比，回滚覆盖 `bootstrap.py`、`requirements-zhs.txt` 与 `zhs/`。ZHS 环境准备失败只告警，不触发启动器文件回滚。
- 手动更新包（`launcher-<version>.zip`）仍可照旧使用：脚本在手动模式下保留 `pause` 与重启提示。

## 已知限制

- 从 v1.7.0 及更早版本升级到 v1.7.1 时，旧版本没有自动应用逻辑，第一次仍需手动运行一次 `.update-staging/应用更新.cmd`；从 v1.7.1 起后续更新全自动。
- ZHS 环境需要 Python 3.13/3.14；找不到合适解释器时只告警，需自行安装后重新准备。
- 更新包不包含 Yatori/Autovisor 第三方核心，行为与上一版一致。
