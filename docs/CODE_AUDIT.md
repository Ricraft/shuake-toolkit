# 代码审查与重构记录

审查日期：2026-07-14

## 结论

项目不是“完全未实现”，但不同子系统成熟度差异很大。统一启动器的大部分前端操作都有后端映射；Autovisor 已覆盖多类课程流程，且单/多账号现已共用同一执行核心；题库具备本地匹配、远程查询和 AI 兜底。主要风险来自巨型函数、页面选择器脆弱、Dashboard 未连接真实执行器，以及真实平台契约测试不足。

以下比例是基于入口、UI/API 映射、真实执行路径和测试覆盖作出的工程估算，不是按代码行机械计算：

| 子系统 | 估算实现率 | 依据 |
|---|---:|---|
| 统一启动器 WebView | 80%–85% | 配置、启停、日志、题库、课程获取和偏好均有桥接；更新与系统集成功能依赖外部环境 |
| 本地题库服务 | 75%–85% | CRUD、去重、匹配、远程与 AI 路径齐全；缺少认证、并发及故障注入测试 |
| Autovisor 单账号 | 65%–75% | 普通课、共享课、见面课、测验流程已实现；页面选择器脆弱且主循环过大 |
| Autovisor 多账号 | 65%–75% | 已复用完整单账号核心并支持固定并发队列；真实多账号页面流程仍待验证 |
| FastAPI Dashboard | 30%–40% | 配置、日志、状态端点存在；任务启动/停止仅修改内存状态，没有连接实际执行器 |
| 整体（按主要使用路径加权） | 约 70%–75% | 核心路径可用，配置/进程回归覆盖已建立；站点变化仍是主要风险 |

## 本轮已修复

1. 新增 `Autovisor/runtime_bootstrap.py`，所有 Autovisor 入口在导入 `slider` 前统一挂载 `runtime_deps`。
2. 单账号和多账号在课程结束后主动取消永久监听协程，避免正常完成却无法退出；任务监控器能正确处理取消状态。
3. 启动器增加原子启动占位，阻止连续点击产生两个 Yatori/Autovisor 进程，并支持取消尚未完成的启动。
4. 刷题模式禁止重复启动，纳入“一键停止”和退出清理，并确保子进程被回收。
5. 题库设置恢复尊重 `ai_enabled`；保存时热更新 AI/自动缓存设置；运行中修改端口会重启服务；非法端口会被拒绝。
6. YAML、INI、JSON 配置改为同目录临时文件 + `os.replace` 的原子写入，降低断电/崩溃造成半文件的概率。
7. Autovisor 账号显示名称现在会持久化，不再重启后丢失。
8. 题库 HTTP 路由改为精确匹配，限制请求体大小，并拒绝非本机网页 Origin，降低恶意网页调用本地服务的风险。
9. 核心更新恢复 TLS 证书验证，增加 ZIP 越界路径检查和下载长度校验；第三方 GitHub 代理默认关闭，仅在显式设置 `LAUNCHER_ALLOW_GITHUB_PROXIES=1` 时启用。
10. 依赖定义集中到 `src/dependencies.py`；基础、可选、Web、开发依赖分组；删除了第二套已漂移的运行时下载实现。
11. pywebview API 适配器从巨型启动器拆到 `src/launcher_api.py`，配置 IO 拆到 `src/atomic_io.py`。
12. 单账号和多账号统一调用 `Autovisor.run(config_path, account_id)`；多账号模块缩减为纯进程编排器，并修复 `--max N` 导致只运行前 N 个账号的问题。
13. 运行配置统一支持未编号/编号小节、公共选项回退、账号 ID 保真、独立 Cookie 和运行时倍速热读取；后台视频任务不再私自重读默认账号。
14. 日志文件加入时间、PID 和账号标识，避免多进程覆盖；声音开关在视频恢复与全国共享课路径中保持一致。
15. 题库客户端移除导入阶段网络探测，并真正使用启动器传入的 `QB_URL`（协议、主机、端口、路径和查询参数）。
16. 增加公开配置示例、Cookie 全目录忽略规则和 pytest 收集边界；运行时 Cookie 不再作为源码维护。

## 仍需优先处理的问题

### P0/P1：直接影响正确性

- `Autovisor/Autovisor.py` 的 `working_loop` 约 900 行、分支复杂度极高。页面导航、卡片扫描、测验、视频和重试状态混在一起，任何站点改版都可能造成跨流程回归。
- FastAPI Dashboard 的 `/api/tasks/start` 与 `/api/tasks/stop` 没有创建或终止真实进程，接口成功响应不能代表任务真的运行。
- 核心更新的官方 GitHub 下载尚无发布方校验和/签名验证。TLS 能保证传输对端，但不能替代制品签名。
- 保存“全部设置”虽然单文件已原子化，但 Yatori、Autovisor、题库三个文件仍不是跨文件事务；中途磁盘错误可能只更新一部分。

### P2：维护性与可观测性

- `统一启动器.py` 仍超过 5,000 行，UI 构建、配置映射、进程管理、课程 API、题库管理和更新对话框应继续拆分。
- `Autovisor/modules/tasks.py` 超过 2,000 行，应按 `question_bank_client`、`test_capture`、`answering`、`video_tasks` 拆分。
- 大量 `except Exception: pass/continue` 会吞掉选择器变化和状态错误。应只忽略已知的 Playwright 超时/页面关闭，并给未知错误加限频日志。
- `Logger` 仍以进程当前目录决定日志位置，内存字符串持续拼接，线程写入也未加锁；Dashboard 列表目录与实际写入目录可能不一致。
- 根目录的 `Untitled-1.py` 和 `绘图.py` 与项目业务无关；在没有版本库可回滚的前提下本轮未删除，建议确认后移入独立实验目录或清理。

## 推荐的下一轮拆分顺序

1. 建立 `CourseAdapter`/`CourseSession` 协议，把普通课、共享课、见面课的扫描与导航变成独立适配器。
2. 将启动器继续拆为 `config_service`、`process_supervisor`、`question_bank_controller`、`course_catalog`、`update_controller`。
3. 为课程适配器增加录制 HTML/API 响应的契约测试，覆盖站点改版而不修改真实账号状态。
4. 拆分 `tasks.py` 的题库客户端、答题、测试抓取和视频后台任务。
5. 最后接通 FastAPI Dashboard 的真实执行器，避免为尚未稳定的重复运行路径继续堆代码。

## 验证状态

- 自研 Python 文件均通过 Python 3.13 语法编译检查。
- 35 项测试通过，覆盖启动器状态、题库 HTTP 策略、Dashboard API、配置归一化、账号隔离、并发队列和自定义题库 URL。
- 单账号与多账号 CLI 冒烟通过，`--help` 不再触发题库网络连接。
- Chrome 插件在初始化阶段报 `Cannot redefine property: process`，因此本轮未能读取现有登录页面；没有将未执行的真实平台登录、播放或答题标记为通过。
