# 代码审查与重构记录

审查日期：2026-07-16

## 结论

项目不是“完全未实现”，但不同子系统成熟度差异很大。统一启动器的大部分前端操作都有后端映射；Autovisor 已覆盖多类课程流程，且单/多账号现已共用同一执行核心；题库具备本地匹配、远程查询和 AI 兜底。`tasks.py` 巨型文件已完成职责拆分，启动器的课程目录、进程监督与配置持久化也已独立，桌面入口已统一为 WebView；主要风险集中到剩余启动器控制器代码、页面选择器脆弱、Dashboard 日志推导仍依赖文本日志而非结构化事件，以及真实平台契约测试不足。

以下比例是基于入口、UI/API 映射、真实执行路径和测试覆盖作出的工程估算，不是按代码行机械计算：

| 子系统 | 估算实现率 | 依据 |
|---|---:|---|
| 统一启动器 WebView | 80%–85% | 配置、启停、日志、题库、课程获取和偏好均有桥接；更新与系统集成功能依赖外部环境 |
| 本地题库服务 | 75%–85% | CRUD、去重、匹配、远程与 AI 路径齐全；缺少认证、并发及故障注入测试 |
| Autovisor 单账号 | 70%–80% | 普通课、共享课、见面课、测验流程已模块化并有状态测试；真实登录与播放契约仍待验证 |
| Autovisor 多账号 | 65%–75% | 已复用完整单账号核心并支持固定并发队列；真实多账号页面流程仍待验证 |
| FastAPI Dashboard | 74%–84% | 配置、真实任务进程启停/状态、子进程日志、会话隔离、去重后的日志推导统计和课程表状态已接通；仍需结构化事件与平台课程字段契约 |
| 整体（按主要使用路径加权） | 约 72%–78% | 核心路径可用，配置/进程回归覆盖已建立；站点变化仍是主要风险 |
